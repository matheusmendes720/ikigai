     7.1 Schema / Drift

     1. Plan-entities schema split-brain (canonical 24-col vs runtime 11-col).
        SQLiteAdapter nunca é chamado pelo commit_node ou MCP ikigai_plan_cycle.
        Reconciliação impossível sem intervenção manual.
     2. No migrations — CREATE TABLE IF NOT EXISTS only, sem versionamento.
     3. Empty persistence/ — diretório existe mas zero files; código de
        propagação vive em src\ikigai\propagation\.

     7.2 MCP / dcode

     4. dcode NÃO conectado ao IKIGAI MCP server — ikigai-maintainer-mcp não
        registrado em nenhum .mcp.json. Único path: Bash → ikigai.bat 
        agent|chat.
     5. IKIGAI MCP server é stdio-only — sem HTTP+SSE, sem toggle. LangChain
        deep agents não conseguem conectar.
     6. Taskdog NÃO é usado via MCP — IKIGAI chama o CLI mesmo sabendo que
        existe um FastMCP server.
     7. _MCP_SESSION_CACHE (tools.py:550) — caches initialize handshake result,
        never invalidated. Server crash → silent failure no próximo call.
     8. NO retry, NO backoff, NO reconnection anywhere em src/. Falhas produzem
        "⚠️ …" strings.

     7.3 Agent / HITL

     9. interrupt_on = {"write_file": True} — edit_file NÃO gated. 6 mutation 
        tools bypass HITL: ikigai_checkpoint (action=set), ikigai_plan_cycle,
        ikigai_sync_vault, solverforge_create_event, tuiboard_update_task,
        tuiboard_create_task, taskdog_create_task, taskdog_complete_task.
     10. No subagents — monolithic single agent with 18 tools.
     11. ikigai_sync_vault split-brain — agent tool writes
         ~/.ikigai/vault/cycle-*.md (tools.py:355), MCP server writes
         data/matheus/ikigai_state/cycle-*.md (server.py:451). Duas paths, dois
         destinos.

     7.4 Observability

     12. @observed_tool decorator não usado — definido mas nunca aplicado a
         production tools. Latent infrastructure.
     13. 3 manual spans only — ikigai.make_agent, ikigai.run_chat.error,
