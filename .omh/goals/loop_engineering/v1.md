## Building blocks

- **Loop engine:** bash (`scripts/dispatch.sh`) + Python orchestrator (`.claude/loop/loop-tick.ts`) on Windows; bash (`.claude/loop/loop-tick.sh`) on POSIX
- **Worker:** sonnet subagent (per ADR-013 dual-model rule)
- **Verifier:** haiku subagent (5-dim scoring: correctness, safety, clarity, complexity, conventions)
- **Orchestrator:** opus (state-machine decisions + worktree management)
- **Verification:** drift net (68 tests) + loop_infra regression (11 tests) — must pass before each commit

## Subagent roles

- **Opus (orchestrator):** picks next milestone, dispatches worker, applies commit, logs tick
- **Sonnet (worker):** implements in worktree, runs tests, returns diff
- **Haiku (verifier):** reviews diff with 5-dim rubric, returns PASS/FAIL/NEEDS_FIX verdict

## Verification policy

- **Inner check:** drift net (every commit, ~0.5s) + SPEC frontmatter validation (every commit)

## Failure modes

- Drift net regression → halt + diagnose (HIGH)
- Number collision between parallel sessions → renumber + update SPEC + roadmap (MEDIUM, observed + recovered)
- Commit conflates multiple milestones → reset --soft + recompose (MEDIUM, observed + recovered)
- Inner repo state-machine drift → restore + .gitignore + check-in (LOW, observed + recovered in M41)
