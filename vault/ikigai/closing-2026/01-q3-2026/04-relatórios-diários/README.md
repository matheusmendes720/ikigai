# Daily Reports — Q3-2026

## Pattern

One file per working day, named `YYYY-MM-DD.md`. Use the template
`vibe-ops/planning/_templates_periodos_v2/05-relatorio-diario.md`.

Each report takes **~10–15 minutes** and is done at end-of-day or first thing next morning.

Skip weekends. On weeks with holidays, skip those days too.

## Expected count

~**66 working days** across 13 weeks (Mon–Fri × 13 = 65, plus 1 buffer).

## Aggregation

Friday's reports feed directly into that week's `../03-revisões-semanais/YYYY-Www.md` review.

Suggested loop:

1. Write `2026-MM-DD.md` after each workday.
2. On Friday, skim all 5 reports.
3. Write `../03-revisões-semanais/2026-Www.md` aggregating the week.
4. Carry open items into next Monday's report.

## The routine that was adopted instead (appended 2026-11-23)

> **This section is appended, not substituted.** The pattern above is the original
> target: one file per working day, ~66 per quarter.
>
> It produced **3 files in ~60 working days** — and then stopped. The reason was
> measured, not guessed: the production runs in bursts (704 commits in 5 weeks,
> then 7 weeks at zero), and a daily routine against that shape produces either
> 7 empty notes or none at all. The **Correction of the Trajectory C1**
> (2026-11-08) replaced the daily routine: **the unit of record is the burst**.
>
> **What exists, and it stays:** `2026-09-05.md`, `2026-09-06.md`,
> `2026-09-07.md` — three records from the W36 and W37 window, all of them
> classified in the quarterly review.
>
> **What does not exist and is not going to:** the other ~57 daily reports. A
> burst is not split into dailies; the week's review **is** the record
> (`03-revisões-semanais/2026-Www.md`).
