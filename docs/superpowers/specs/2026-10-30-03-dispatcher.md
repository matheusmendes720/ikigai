# SPEC-03 — O Dispatcher: as 6 skills rodam sem o grafo

**Date:** 2026-10-30 · **Status:** proposed · **Depends on:** SPEC-01 · **Blocks:** SPEC-04

## Goal
`life skill-run <nome> --json` executa qualquer skill e devolve um `Proposal` — **sem LLM, sem LangGraph, sem MCP gateway**.

## Por que agora
As 6 skills já estão na forma certa: todas têm `SKILL_NAME` + `run_skill(...) -> Proposal` e importam só `agents.v2.proposals` + `agents.v2.skills.cadence` (verificado: `ikigai_daily.py:16-21`, `taskdog_triage.py:132-135`). **O desacoplamento do grafo já existe.**

O que não existe é o dispatcher. Hoje o único caminho é `interfaces/cli/invoke_skill.py` (538 LOC) → `agents.v2.graph.NODES` → `mcp_bridge` → gateway → tools. E esse caminho está **quebrado em runtime**: `mcp_bridge.py:88-130` envolve 9 tool names que não existem em `server.py` (P0 em `2026-09-10-system-review-diagnosis.md`).

## Anti-padrão que este spec evita
`invoke_skill.py:420-433` valida `entry_point` contra `NODES` — o grafo vira **filtro obrigatório** de toda skill. E `meta_plan.md` tem `entry_point: meta_plan`, que não está em `NODES` → `ValueError`. Um grafo como gate de entrada para código que não precisa dele.

## Decisões
- **D1** — Novo dispatcher `life skill-run`, ~150 LOC, em `interfaces/cli/skill_run.py`. `invoke_skill.py` **não é removido aqui** (SPEC-05 remove) — coexistem, e o novo é o caminho oficial.
- **D2** — **Convenção uniforme por introspecção.** As assinaturas divergem:
  | Skill | Assinatura |
  |---|---|
  | `ikigai_daily`/`weekly`/`monthly`/`quarterly` | `run_skill(today=None)` |
  | `taskdog_triage` | `run_skill(tasks=None, today=None)` |
  | `vault_intent_extract` | `run_skill(markdown="")` |

  O dispatcher **introspecta** (`inspect.signature`) e só passa os kwargs aceitos. Flags: `--date`, `--markdown`, `--tasks <json>`. **Nenhuma skill muda de assinatura.**
- **D3** — `metadata` dinâmico sobrevive ao JSON. `Proposal.to_dict()` = `asdict(self)` (`proposals.py:61`); `asdict` só serializa campos declarados; `ikigai_daily.py:97` anexa `metadata` dinamicamente → **as sugestões do daily somem no JSON**.
- **D4** — Corrigir `entry_point` dos 4 manifests. **Verificado no disco** (`src/ikigai/src/agents/v2/skills/*.md`, todos na **linha 4**): `daily.md` → `surface_intentions` · `weekly.md` → `observe` · `monthly.md` → `observe` · `quarterly.md` → `observe`. Nenhum é um callable `run_skill` — os 4 apontam para **nós do grafo**, que é exatamente o filtro que a SPEC-03 quer remover. Passam a apontar para o callable do módulo. `meta_plan.md:4` → `meta_plan` (também nó do grafo): fica **fora do registry** até existir (o dispatcher reporta `unknown skill`, não quebra).

  > **Verificado (2026-10-30):** `generate_proposal` **existe** — `src/ikigai/src/agents/v2/nodes/meta_plan/generate_proposal.py:97`. E `meta_plan` **não** está em `graph.NODES`: foi acrescentado a uma **view local** em `subgraph.py:742` (`if "meta_plan" not in _nodes`). Logo o `entry_point: meta_plan` falha na validação de `invoke_skill.py:420`, que compara contra `graph.NODES`. Nota para o SPEC-05: `subgraph.py` está na lista de remoção, e é ele que carrega `make_meta_plan_subgraph` (`:684`) — se `meta_plan` sair do registry antes do corte, a dependência morre junto.
- **D5** — Corrigir o caminho do cron quebrado: `.claude/skills/taskdog-triage/SKILL.md:113` aponta `python -m interfaces.cli.main v2 daily --skill taskdog-triage`. **`interfaces.cli.main` não existe** (o módulo é `interfaces.cli`).

## Contrato
```bash

```
```python
# interfaces/cli/skill_run.py
@app.command(name="skill-run")
def skill_run(name: str, json_out: bool = typer.Option(False, "--json"), ...):
    try:
        mod = get_skill(name)
    except KeyError:
        typer.echo(f"skill desconhecida: {name}", err=True)
        raise typer.Exit(2)
    sig = inspect.signature(mod.run_skill)
    kwargs = {}
    if "date" in sig.parameters and date_arg: kwargs["date"] = date_arg
    if "markdown" in sig.parameters and markdown_arg: kwargs["markdown"] = markdown_arg
    if "tasks" in sig.parameters and tasks_arg: kwargs["tasks"] = json.loads(tasks_arg)
    result = mod.run_skill(**kwargs)
    payload = {**result.to_dict(), **getattr(result, "metadata", {})}   # D3
    print(json.dumps(payload, default=str, ensure_ascii=False))
```
Exit codes: 0 ok · 2 skill desconhecida · 3 erro da skill.
