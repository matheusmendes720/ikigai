# SPEC-05 — O Corte

**Date:** 2026-10-30 · **Status:** proposed — **GATED** · **Depends on:** 01, 02, 03, 04 · **Blocks:** —

## Goal
Remover ~15.000 linhas de harness morto, mantendo o que produz efeito, e parar o loop de daemons.

## Por que agora
**Depois**, não antes. Complexidade é a segunda prioridade; o input port é a primeira. Cortar antes de 01–04 rodarem deixa um sistema menor e igualmente inutilizável.

A ordem importa por uma razão concreta: **`td gantt` é um leaf de `taskdog_cli.py:61`**. Cortar o sprawl de taskdog sem antes re-hospedar o CLI do Gantt **mata o artefato visual**.

## Anti-padrão que este spec evita
Cortar por contagem de linhas. Cada remoção aqui tem **fecho de dependência** verificado. E tudo vai para branch própria, recuperável no git.

## Decisões
- **D1** — Branch `chore/vanilla-pivot`, tudo removível com `git revert`. Nada é apagado do histórico.
- **D2** — Ordem fixa: **(a) re-hospedar `td_gantt`** → **(b) podar drift net** → **(c) `git rm` do harness** → **(d) matar daemons** → **(e) AG3 discard**.
- **D3** — O drift net encolhe de 2.977 para ~800. Mantém: regex UEID, append-only, vault sole-writer. **Deleta as contagens de tool** — quebram a cada corte e não protegem nada. **Adiciona** o teste "nenhuma skill importa `graph`" (do SPEC-03).
- **D4** — O gateway MCP custom sai inteiro. Se o `hermes` precisar dirigir as interfaces, o caminho é `fastmcp` sobre a CLI (~50 LOC), porque `--json` já é convenção em tudo.
