# SPEC-02 — O Writer: a ponte chat → vault

**Date:** 2026-10-30 · **Status:** proposed · **Depends on:** SPEC-01 · **Blocks:** SPEC-04

## Goal
Você termina uma conversa de planejamento e **um comando** deixa a nota no vault — datada, no lugar certo, com o formato do template.

## Por que agora
O canal humano→agente foi projetado (`vault/ikigai/templates/sonho-log.md`: *"1–3 bullets · <2 min · atrito-alvo: zero"*) e teve 3 usos (2026-09-05, -06, -07) e depois silêncio. Não porque o formato estava errado — porque exigia **abrir arquivo à mão**. O sistema tem um writer (`sys_ikigai.vault.vault_write`, atômico, com lock, sole-writer por ADR-012) e um template. **Falta o botão.**

## Anti-padrão que este spec evita
O relatório `2026-09-14-ikigai-rebuild-honest.md` escreveu um plano inteiro para "reconstruir" coisas que já existiam, com 20 arquivos marcados MISSING e testes que asseveravam stubs. **Este spec não reconstrói nada.** `vault_write` existe (138 LOC, testado), o template existe, o caminho existe (SPEC-01). O delta é um comando.

## Decisões
- **D1** — Novo comando `life vault-note`, **não** um hook. Hook `Stop` exigiria detectar "a sessão produziu delta de planejamento" — classificação frágil, e falha silenciosa é o pior modo de falha. Comando explícito é determinístico.
- **D2** — Escrita **append-only** sobre arquivo existente. `vault_write` faz `os.replace` (substitui). Para uma nota diária que pode receber várias entradas no mesmo dia, o writer faz **read → concat → write**, **com o lock adquirido uma única vez**.

  > **Correção (verificada 2026-10-30):** `VaultLock` (`sys_ikigai/vault/lock.py:20`) **não é reentrante** — `__enter__` abre um novo fd e trava o byte 0 do arquivo (`msvcrt.locking` no Windows, `fcntl.flock` no POSIX; flock é por open-file-description, então o processo trava em si mesmo). Envolver `vault_write` — que **já** adquire o lock — em outro `with VaultLock(...)` **deadlock**.
  > **Logo:** o append é um **novo primitivo no pacote do vault**: `vault_append(vault_root, vault_path, frontmatter_fields, body, actor)` em `sys_ikigai/vault/vault_write.py`, que adquire o lock **uma vez** e faz read→concat→write dentro da mesma seção crítica. `interfaces/cli/vault_note.py` chama `vault_append`. **Nunca** `with VaultLock(...): vault_write(...)`.
- **D3** — Frontmatter no formato exato do template `sonho-log.md`: `type: planning_note`, `note_version: 1.0`, `date`, `cluster: ikigai/plan`, `parent_sonho`, `triggered_by: manual`, `status: draft`, `tags: [planning-note, ikigai/plan]`.
- **D4** — `parent_sonho` obrigatório mas tolerante: se `00-sonho/` tiver conteúdo, descobre o `sonho-id`; se estiver vazio, escreve `sonho-tbd` e **imprime aviso** — não falha. Um objetivo real é ação humana, não pré-requisito de máquina.
- **D5** — `--dry-run` imprime o markdown sem escrever.

## Interfaces
- **Consumes:** `sys_ikigai.vault.vault_write` (sole writer, ADR-012), `sys_ikigai.vault.vault_append` (**novo**, D2 — append com lock adquirido uma vez), `src.contracts.vault_paths.daily_path`, `vault/ikigai/templates/sonho-log.md`
- **Produces:** arquivo em `<quarter>/04-relatórios-diários/YYYY-MM-DD.md` + entrada em `.vault_audit.log` com `actor=user`

## Contrato
```bash
life vault-note --delta "O que mudou" [--why "Por quê"] [--impact "Impacto"] \
                 [--date YYYY-MM-DD] [--sonho <id>] [--dry-run]
```
Humano:
```
nota escrita: vault/ikigai/closing-2026/02-q4-2026/04-relatórios-diários/2026-10-30.md
  1 bullet(s) · sha256 9f2c…  · actor=user
```
`--json`:
```json
{"written": true, "vault_path": "…/2026-10-30.md", "sha256": "…", "actor": "user", "bullets": 1}
```
