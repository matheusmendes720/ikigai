## O problema que esta série resolve

O sistema não é usado porque **tem duas árvores de vault e todo caminho automatizado lê a árvore vazia**.

| Leitor | Caminho que usa | Existe? |
|---|---|---|
| `cadence.py:78` (`daily_path`) | `vault/daily/YYYY-MM-DD.md` | **não** |
| `cadence.py:84` (`weekly_path`) | `vault/weekly/YYYY-Www.md` | **não** |
| `cadence.py:88` (`monthly_path`) | `vault/monthly/YYYY-MM.md` | **não** |
| `cadide.py:93` (`quarterly_path`) | `vault/quarterly/YYYY-Qn.md` | **não** |
| `vault_intent_extract.py` | `vault/daily/{date}.md` | **não** |

Consequência: `ikigai_daily.py:64` faz `read_vault_note(daily_path(yesterday))` → arquivo ausente → `""` → **a skill sempre emite "Dia sem registro. E os testes passam: `test_m162_cadence_helpers.py` assevera a **string** do caminho, nunca que exista conteúdo nele. É o teste-tautologia em estado puro — a classe de teste que a rede de drift protegia em vez de comportamento.

## A convenção de operação (a parte que não é código)

Leia antes de 02.

### 1. O vault é a única porta de entrada
O sistema lê do vault. Você escreve numa janela de chat. Enquanto essas duas pontas não estiverem ligadas, todo o resto é teatro.

### 2. Toda sessão de planejamento termina com uma nota
O template `vault/ikigai/templates/sonho-log.md` já existe e já diz o formato certo: **1–3 bullets, <2 min, atrito zero**. Teve 3 usos (2026-09-05, -06, -07) e depois silêncio — porque exigia abrir arquivo à mão. **O spec 02 torna isso um comando**, não um hábito.

### 3. O vault tem 5 diretórios e cada um tem dono
```
vault/ikigai/closing-2026/<NN>-q<N>-<YYYY>/
  00-sonho/               SONHO — o objetivo. Escrito por você. 1 por trimestre.
  01-plano-trimestral/    o plano do trimestre. Fases com Início/Fim.
  02-onda-<n>/            janelas das ondas. 1 arquivo por onda.
  03-revisões-semanais/   revisões. Nome estável: YYYY-Www.md
  04-relatórios-diários/  notas diárias. Nome estável: YYYY-MM-DD.md
```

### 4. Quem escreve o quê
| Ator | Escreve | Como |
|---|---|---|
| **você** | `00-sonho/`, `01-plano-trimestral/`, `02-onda-*/` | mão, no seu Obsidian |
| **você** | `04-relatórios-diários/` | `life vault-note` (spec 02) — nunca à mão |
| **agente** | via `vault_write` (ADR-012) | proposal → `--approve` → fila → propagado |
| **nenhum** | `03-revisões-semanais/` | só quando **você** revisar de verdade |

### 5. A regra de ouro
> **Onde há invariante, código. Onde há julgamento, prompt.**

- **Código:** formato UEID, sole-writer do vault, append-only, rename atômico, idempotência em `ueid`, thresholds determinísticos, renderização do Gantt.
- **Prompt:** "sugerir 3–5 melhorias em pt-BR", "surface intentions", score vectors, balance, plan, reflect, gantt_suggest.

## O loop que executa esta série (`converge`)

A série não avança sozinha. Um workflow multi-agente avança — **com uma regra que mata o modo de falha que te pegou**: o hill-climb que produziu "No change recommended" ×5 sem mover nada.

**Workflow:** `life/.claude/workflows/converge.js` (5 fases)

| Fase | O que faz | Agentes |
|---|---|---|
| **Recon** | ground truth: branch, specs marcados `[x]`, baseline de teste, streak de ciclos sem delta | 1 |
| **Select** | escolhe **uma** task atômica do spec atual + o comando que a prova | 1 |
| **Execute** | implementa só essa task, roda a verificação, confere em disco | 1 |
| **Verify** | **dois adversariais em paralelo**: comportamental (o teste morre se a implementação for revertida?) e regressão (quebrou algo?) | 2 |
| **Gate** | DELTA / NO-DELTA / STOP · marca `[x]` no spec · commita na branch `chore/vanilla-pivot` | 1 |

**As 3 regras que importam**

1. **Só código e testes.** O loop nunca escreve plano, spec, ADR ou changelog. É a regra que impede a série de virar mais documentação — que foi como ela nasceu.
2. **Delta observável ou nada.** Um ciclo só conta se o teste novo *morre* quando a implementação é revertida (mutation check) **e** o gate mais barato continua verde. Um "pass" indevido mantém o loop vivo sobre trabalho falso — é exatamente o que o hill-climb fazia.
3. **Auto-parada.** Dois ciclos consecutivos sem delta → o loop **para**. Sem isso, um loop de 30 min reproduz o `No change recommended` em loop.

**Segurança:** o SPEC-05 (corte de ~15k LOC) **exige go explícito do owner** — o loop para ao chegar nele e nunca faz `git rm`. `git stash` / `checkout --` / `reset` / `clean` estão proibidos. Só o Gate commita, em branch própria, com footer `Verification:`. Arquivos já sujos no início do ciclo são intocáveis.

**Estado:** `life/.claude/loop/logs/converge-state.json` (`noDeltaStreak`, `doneTasks`, `lastStatus`).

**Agendamento:** a cada 30 min (`:13` e `:43`). Ao parar, o job se apaga.

FASE VERIFY - lente COMPORTAMENTAL. Seu trabalho e tentar DERRUBAR o que foi feito.

Task: ${selected.taskId}
Arquivos: ${(executed.filesWritten || []).join(', ')}
Comando de verificacao: ${selected.verificationCommand}

1. Leia o teste/verificacao adicionada. Ela assere COMPORTAMENTO ou so CONSTANTES/STRINGS? (assever "o path e vault/daily/X" e tautologico; asser "a skill leu a nota que existe" e comportamento)
2. Mutation check: reverta mentalmente a implementacao - o teste falharia? Se puder reverter em disco com seguranca (git checkout do arquivo e PROIBIDO; NUNCA stash), descreva o raciocinio e diga qual foi.
3. O teste cobriria uma implementacao deliberadamente errada? Se nao, killsMutation=false.
4. Verdict "pass" so se for comportamento E matar mutacao. Qualquer tautologia -> "fail".

Seja rigoroso. Um "pass" indevido mantem o loop vivo sobre trabalho falso - exatamente o modo de falha que este loop existe para eliminar.`,
    { schema: BEHAVIOR_SCHEMA, label: 'verify:behavioral', phase: 'Verify', effort: 'high' }
  ),
  () => agent(
    RULES + `
FASE VERIFY - lente REGRESSAO. Seu trabalho e encontrar o que QUEBROU.

Task: ${selected.taskId}
Arquivos alterados: ${(executed.filesWritten || []).join(', ')}
Verificacao da task: ${selected.verificationCommand}

1. Rode o gate mais barato que cubra os arquivos alterados (pytest do pacote tocado; senao ruff check nos arquivos). Reporte o resultado real.
2. Os invariantes que importam continuam valendo? Confira o que for barato: formato UEID (4 partes); vault append-only e sole-writer; idempotencia em ueid; nenhuma skill importando o grafo.
3. Se a task for do spec 01: "grep -rn vault/daily src/" deve retornar 0 hits.
4. Verdict "pass" so se nada quebrou. Liste em broken o que quebrou, com path:linha.

Nao conserte nada. So reporte.`,
    { schema: REGRESSION_SCHEMA, label: 'verify:regression', phase: 'Verify', effort: 'high' }
  ),
])

const verdicts = [behavior, regression].filter(Boolean)
const verifyOk = verdicts.length === 2 && verdicts.every(v => v.verdict === 'pass')

phase('Gate')

const isDelta = !!(executed.ok && executed.verificationPassed && verifyOk && !executed.touchedVault)
const newStreak = isDelta ? 0 : (recon.noDeltaStreak || 0) + 1

const gate = await agent(
  RULES + `
FASE GATE. Feche o ciclo.

Execute: ok=${executed.ok} verificationPassed=${executed.verificationPassed} files=${(executed.filesWritten || []).join(', ')}
Verificacoes: ${JSON.stringify(verdicts)}
DELTA=${isDelta} · streak=${newStreak}
${dirtyNote}

Faca:
1. Escreva o estado em ${STATE} (JSON): {"noDeltaStreak": ${newStreak}, "lastTask": "${selected.taskId}", "lastStatus": "${isDelta ? 'DELTA' : 'NO-DELTA'}", "doneTasks": [...]}
   doneTasks = lista acumulada (leia a existente e acrescente "${selected.taskId}" se DELTA).
2. Se DELTA:
   a) marque como concluida no arquivo de spec, troque "- [ ]" por "- [x]" em "${selected.taskId}". So essa. Nao reescreva o resto do arquivo.
   b) Commit na branch ${BRANCH}: commite APENAS os arquivos da task + o spec markdown. Mensagem Conventional Commits. Footer: "Verification: ${selected.verificationCommand}" Sem trailer Co-Authored-By. Se a branch nao existir, crie-a a partir da branch atual. Se a arvore tiver arquivos sujos de outra origem (${(recon.dirtyFiles || []).join(', ')}), NAO os inclua no commit - use git add por caminho explicito.
3. Se NO-DELTA: NAO marque checkbox, NAO commite. So registre o estado.
4. Reporte: o que mudou, o que falhou (se falhou), a razao.

Nada de plano, nada de spec nova, nada de ADR.`,
  { label: 'gate:close-cycle', phase: 'Gate', effort: 'medium' }
)

if (!isDelta && newStreak >= 2) {
  return {
    status: 'STOP',
    reason: '2 ciclos consecutivos sem delta observavel - auto-parada (regra anti-hill-climb)',
    streak: newStreak,
    task: selected.taskId,
    executed,
    verdicts,
    gate,
    unreached: recon.unreached,
  }
}

return {
  status: isDelta ? 'DELTA' : 'NO-DELTA',
  task: selected.taskId,
  title: selected.title,
  files: executed.filesWritten || [],
  verification: selected.verificationCommand,
  verificationPassed: executed.verificationPassed,
  verdicts,
  streak: newStreak,
  next: recon.nextTask,
  unreached: recon.unreached,
  gate,
}
