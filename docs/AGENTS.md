# docs

## OVERVIEW
Architecture history, design proposals, audits, and generated documentation; score 8 because this is a large, distinct documentation domain.

## STRUCTURE
```
docs/
├── architecture/     # dated architecture reports and readiness notes
├── decisions/        # pending adjudications, separate from canonical ADRs
├── design-system/   # proposed canvas, contracts, fork, and UI patterns
├── diagnostics/      # dated forensic audits and migration evidence
├── research/        # external landscape research
├── specs/           # focused specifications
├── superpowers/     # historical plans, specs, and glossaries
└── openwiki-visualizer/ # generated static wiki export
```

## WHERE TO LOOK
| Task | Location | Notes |
|------|----------|-------|
| Find the documentation index | `README.md` | Useful entry point, but contains pre-pivot PAV references |
| Read current operational concepts | `CONCEPTUAL_MODEL.md`, `SYSTEMS_TOPTOPOLOGY.md` | Read their supersession banners before relying on them |
| Review historical architecture | `ARCHITECTURE_INDEX.md` | Retained pre-pivot index, explicitly superseded |
| Inspect dated audits | `diagnostics/` | Evidence snapshots, not live contracts |
| Review proposed patterns | `design-system/` | Design material; implementation status must be checked in code |
| Find implementation plans | `superpowers/plans/`, `superpowers/specs/` | Historical planning record, often ahead of or behind code |
| Inspect unresolved choices | `decisions/pending/` | Recommendations are non-binding until adjudicated |
| Read external research | `research/` | Point-in-time technology landscape |
| Work on the static wiki viewer | `openwiki-visualizer/` | Generated by the scheduled OpenWiki workflow |

## CONVENTIONS
- Historical documents remain readable but carry `SUPERSEDED`, `PENDING`, or dated status markers; inspect those markers before using their conclusions.
- Canonical architectural decisions live under the repository's `code-docs/adr/` tree, not in this convenience documentation area.
- The corpus mixes Portuguese and English; preserve the language of the section being edited.
- Use dated folders and explicit status headers for audits so evidence is not mistaken for current behavior.
- The OpenWiki visualizer is regenerated output; source changes belong upstream, while exported files are updated by the workflow.
- Plans and specifications describe intended work, not proof that the code exists or behaves as written.

## ANTI-PATTERNS
- NEVER use `README.md`, `ARCHITECTURE_INDEX.md`, `SYSTEMS_TOPOLOGY.md`, or `CONCEPTUAL_MODEL.md` as unconditional current architecture; they contain acknowledged pre-pivot PAV framing.
- NEVER infer implementation status from a plan, proposal, audit, or pending decision; verify the corresponding contract and code.
- DO NOT treat recommendations in `decisions/pending/` as approved policy.
- DO NOT hand-edit `openwiki-visualizer/` expecting the change to persist; the scheduled export can replace it.
- DO NOT resurrect the archived PAV subsystem merely because old documents still reference it.
- Avoid creating new competing indexes without linking the authoritative source and marking the document's status.
