## CONVENTIONS

- Pydantic v2 strict is the default contract shape: `model_config = ConfigDict(frozen=True, extra="forbid")` (`contracts/proposal.py`, `chat/schema.py`, `solverforge_calendar/models.py` via `_Base`, `tuiboard/models.py` via `_Base`, `strategics/loader.py`). Deviation: `paperclipai_bridge/schemas.py` uses `class X(BaseModel, frozen=True)` instead of `model_config`, so those models are frozen but do not forbid extra fields.
- `from __future__ import annotations` at the top of every module except `src/life_tatics/domain/{screentime,time_blocks}.py`.
- Heavy ADR/decision citation in module docstrings (`ADR-009`, `ADR-013`, `ADR-014`, `ADR-024`, `ADR-028`, `ADR-030`, `Plan D Task B.1`, `decision #3`) plus `__all__` on package entrypoints.
- Dual import identity is live: dotted-prefix (`src.ikigai...`, `src.contracts.common`) and bare (`contracts.common`, `strategics.loader`, `tuiboard.models`, `solverforge_calendar.models`) styles coexist; `src/agents/__init__.py` merges the two `agents` trees via `__path__`.
- Env-var configuration instead of config files: `TUIBOARD_DATA_DIR`, `TUIBOARD_SNAPSHOTS_DIR`, `SOLVERFORGE_DATA_DIR`, `LIFE_VAULT_ROOT`, `PAPERCLIP_CHECKPOINT_DB`, `LIFE_PAPERCLIP_BRIDGE_PORT`, `IKIGAI_DEV_MODE=1`, `IKIGAI_DISABLE_OTEL=1`, `LANGSMITH_*`, `LANGFUSE_*`.
- Entry-point convention: `if __name__ == "__main__": raise SystemExit(main())` for CLI bins; MCP servers call `server.serve_forever()`; `src/ikigai/bin/__init__.py` requires import-time side-effect freedom (no logging config, no threads, no gateway construction).
- Atomicity: chat writes use tempfile + `os.replace`; tuiboard snapshots write `.tmp` then `os.replace`; solverforge uses SQLite UPSERT on `ueid`.
- Frozen dataclasses for runtime value objects (`SessionSummary`, `ServeOptions`, `AggregatedTask`) vs Pydantic models for wire contracts.
- Test artifacts follow a "HYBRID" pattern: the e2e pytest fixture regenerates `src/ikigai/tests/reports/b7-4-report.md` in the B3-B4 implementer-report format.
- Naming deviations: two unrelated `Proposal` classes (`ikigai.contracts.proposal.Proposal` with `approval_state` vs `chat.schema.Proposal` with `status`); UEID regex is duplicated and inconsistent — ADR-014 form `[a-z]{2,5}` in `contracts/proposal.py` vs `[a-z]{2,10}` in `chat/schema.py`; `chat/schema.py` keeps legacy status spellings (`open`/`OPEN`, `closed`/`CLOSED`).
- Pydantic models use mutable list/dict defaults (`blocked_by: list[UEID] = []`, `tags: list[str] = []`).

## ANTI-PATTERNS

- Soul profiles carry three parallel "7 never-do rules" sets (planner / critic / stoic): never claim PAV/QHE/regime is alive (archived); never invent cycle/horizon numbers; never write `vault/.kill_switch.md`; never override a user-stated priority without restating it; never invoke archived scoring code under `src/ikigai/src/ikigai/core/scoring/`; never propose more than 5 parallel workstreams; never claim evidence without a file path. Critic: one question per turn, never multi-question, never propose alternatives before the answer, never assert a counter-position without `vault/`/`strategics/` evidence, never propose a plan, never use "should/must/ought" without citation. Stoic: never equate effort with progress, never act outside the controllable subset, never minimize the stressor, never recommend emotional suppression, never use urgency without a calendar deadline, never propose multi-action responses.
- Append-only: `vault/ikigai/runtime/sessions/` MUST NOT delete entries; re-storing a `session_id` appends a timestamped section and never overwrites; the strategics loader NEVER writes.
- Agent layer is planner-only per ADR-013: no PAV math execution, `IKIGAI_TOOLS = 12` planning tools, mesh v1 create-action only (`src/agents/__init__.py`). The scoped A2UI test `test_a2ui_schema.py` nevertheless parametrizes `create|update|delete|done`, which contradicts that stated v1 constraint — treat mesh create-only as authoritative.
- No LLM in pipeline steps: intent classifier is keyword-only (ADR-007), investigation dispatcher is "NO LLM", meta-plan context fetch is read-only ("All three fetches are read-only. No writes here.").
- Proposal safety: `VaultWriteOp` rejects SONHO writes unless `actor_required == "user"`; generated proposals always start `approval_state="pending"`.
- Observability is best-effort and must never block the host app; a known-noise filter drops three OTel ERROR records while keeping CRITICAL/FATAL visible.
- Gateway: `IKIGAI_DEV_MODE=1` must never spawn the stdio subprocess; an unbound `GatewayClient` intentionally raises `RuntimeError` instead of silently falling back; `reset_gateway_client_singleton` exists to prevent cross-test state leak.
- Path-traversal guards before filesystem access: soul profile names reject separators/`..`; `session_id` restricted to `[A-Za-z0-9._-]{1,128}`.
- Gate semantics differ by design: Paperclip cost + wall-clock gates are fail-OPEN, risk gate fail-CLOSED; unknown `sf_replan` hard constraints are ignored (fail-open).
- A2UI wire constraints: JSON-RPC version `2.0` only, error codes restricted to -32799..-32000, unknown methods/actions rejected.
- Documented side effect to preserve: `sf_schedule` upserts the row even when status is `conflict` or `blocked` (caller decides retry).
