## CONVENTIONS

- **Flat import root.** `vibe-ops/src` sits on `sys.path`; siblings are imported as `pipeline.x`, `models.x`, `storage.x`, `schemas.x` — *not* the repo-root `src.contracts` dotted style used elsewhere in this monorepo. Tests replicate this by `sys.path.insert(0, Path(__file__).resolve().parents[1] / "src")` with `VIBE_OPS_SRC`, then `# noqa: E402` on every post-bootstrap import.
- **Mixed absolute/relative intra-package imports.** `gap_engine.py` and `sync_orchestrator.py` use `from .knowledge_tree import ...` / `from .frontmatter_parser import ...`; everything else uses absolute `from pipeline.x import`. `__init__.py` uses relative `from .x import` throughout.
- **`from __future__ import annotations` is inconsistent** — present in 9 of 30 pipeline modules (cognitive_debt_tracker, enrichment_engine, hypothesis_evaluator, ingestion_engine, learning_outcome_processor, mvl_orchestrator, rice_exporter, schema_registry) and absent in the rest, contradicting the repo-wide rule in root AGENTS.md ("`from __future__ import annotations` at top of every module").
- **Docstrings/comments are mixed PT-BR/en.** Module and class docstrings are Portuguese ("Orquestrador mestre do Data Mesh", "Enriquece metadados"), while newer modules (`hypothesis_evaluator`, `rice_exporter`, `knowledge_telemetry`, `sync_orchestrator`) use English docstrings with an explicit `Source: .omo/plans/<plan>.md (T<n>)` provenance header.
- **Config lives in `ClassVar` dicts**, not YAML: `FrontmatterParser.MODEL_MAP` (24 entity types), `PolicyEngine.POLICY_MAP` (per-state setpoints), `FKResolver.FK_SCHEMA`. Only `SchemaRegistry` reads a real YAML registry (`vibe-ops/schema_registry/registry.yaml`).
- **`str, Enum` is deliberate.** `ContractStatus`, `PipelineState`, `EventType` all carry `# noqa: UP042 - keep (str, Enum) member repr for DB payloads` — the enum value is serialized straight into DB rows.
- **Idempotency key = `upstream_id`.** SHA-256 truncated to 12 hex chars, computed from `id`+`title` (`enrichment.MetadataEnricher.compute_upstream_id`) or from the whole payload (`roadmap_sync_ingest.upsert`); `ON CONFLICT ... DO UPDATE` upserts everywhere. ADR-001 §2.1 lists Idempotência as an architectural principle.
- **Fail-fast gatekeeping.** `MVLOrchestrator.ingest_markdown` validates first and writes a `FAILED_VALIDATION` / `CONTRACT_VOLATION` state trace instead of persisting invalid payloads; `SchemaRegistry` returns a `ValidationResult` with an `errors` list.
- **Explicit state machine, no boolean flags.** ADR-002 §3.1 explicitly rejects "tudo via flags boolean"; every transition must have trigger, pre-condition, post-condition and audit log. `PipelineStateMachine.transition` writes one `StateMachineORM` row per transition.
- **Three canonical representations per stateful entity**: YAML schema → Pydantic v2 model → SQL DDL (ADR-002 §2.1), with the YAML declared *first* (Schema-First).
- **Schema-first + deterministic.** No LLM in the daily/weekly pipeline — "apenas aritmética + funções algébricas" (ADR-001 §2.1, ADR-004 §2.2: "NÃO usar LLMs no pipeline diário").
- **Fully local, zero cloud.** SQLite (SoT) + ChromaDB (vectors) + Obsidian markdown; OpenAI embeddings only as a configurable alternative, never default.
- **Naming.** Modules snake_case, classes PascalCase, module-level constants UPPER_SNAKE; entity keys are snake_case strings (`"study_topics"`, `"planning_entities"`, `"vault_sync_state"`).
- **Tests**: pytest, class-per-behaviour (`TestModelMapRegistry`, `TestComputeRiceScore`), fixtures from `tests/conftest.py` (`fixture_vault`, `temp_vault`, `temp_db`, `sync_engine`, `populated_sync_engine`), fixture vault at `tests/fixtures/vault` (5 subdirs), one `pytest.mark.e2e` marker (`test_full_sync_cycle.py`), `pytest.approx` for float assertions, `pytest.raises(ValidationError)` / `pytest.raises(ValueError, match=...)` for validation contracts.
- **Migrations** are numbered SQL files in `vibe-ops/migrations/` (`001_…` → `005_vault_sync.sql`) and are asserted idempotent (script executed twice in `test_migrations.py`).

## ANTI-PATTERNS

Explicit prohibitions found in scope:

- **No LLM in the daily pipeline.** ADR-004 §2.2: "NÃO usar: LLMs no pipeline diário (apenas retrieval, não geração)". ADR-001 §3.5 rejects the "LLM-decision-maker" alternative.
- **No boolean-flag state.** ADR-002 §3.1 rejects flag combinations (illegal states possible, history lost).
- **No runtime-only validation.** ADR-002 §3.2 rejects "Sem contratos, validar em runtime".
- **No Event Sourcing / Kafka-like event-driven bus.** ADR-002 §3.3 and ADR-005 §3.4 reject both "por complexidade".
- **No monolithic unified schema.** ADR-001 §3.4 and ADR-005 §3.2 reject the single-schema/single-Pydantic monolith ("mudança em 1 cluster quebra todos").
- **No raw FK spaghetti.** ADR-005 §3.3 rejects "Sem contratos (TUDO é FK direto)".
- **No cloud dependency** (Fully Local), **no Neo4j in the default path** (ADR-004 §3.4 — optional only).
- **No planning-document overwrite** — Append-Only (ADR-001 §2.1).
- **Rejected alternatives in ADR-002 §2.1**: always `frozen` Pydantic contracts and a canonical SQL DDL; contracts live in `vibe-ops/src/contracts/*.yaml` + `src/models/*.py` + `src/storage/schema.sql`.
- **DEPRECATED** appears as a `ContractStatus` member (`schema_registry.py:37`) — the registry's lifecycle vocabulary is `ACTIVE | DRAFT | DEPRECATED`; no code path currently consumes the deprecated status.
- **Deprecation of legacy sync**: `tw_sync.py` is explicitly labelled "Legacy/Basic Taskwarrior sync logic", superseded by `tw_sync_adapter.py`.
- **Scoring is not the sync layer's job.** `test_sync_code_to_vault.py:192`: "The sync layer writes field *presence* — it never computes scores"; :226: "Per attribution §3 the orchestrator/sync layers must not execute" scoring. RICE lives only in `pipeline/rice_exporter.py`.
- **Code-shape anti-patterns present in the tree** (not prohibitions, but violations to be aware of):
  - `print()` instead of `logging`: `frontmatter_parser.py:94`, `reverse_sync.py:23,25`.
  - Deprecated `datetime.utcnow()` (naive UTC): `analytics_emitter.py:28`, `enrichment_engine.py:47,102`, `ingestion_engine.py:99,158`, `metadata_catalog.py:37`, `mvl_orchestrator.py:164`, `pipeline_state_machine.py:31`, `policy_engine.py:107`, `roadmap_sync_ingest.py:79`.
  - Stub / no-op implementations: `tw_sync_adapter.py` (`full_pull` returns `[]`, `full_push` is `pass`), `fk_resolver.validate` always returns `True`, `enrichment.enrich_project` returns the input unchanged, `gap_engine.py:27` "mock por enquanto", `code_review_sync.py` and `study_manager.py` are 0-byte files.
  - Raw SQL string interpolation in `contracts._get_all_entities` (`f"SELECT * FROM {table_name}"`) and direct `adapter.sqlite._get_connection()` private-API use from `contracts.py` / `learning_outcome_processor.py`.
  - Cross-layer private-call coupling: `LearningOutcomeProcessor._update_topic_depth` calls `self.contract_engine._increment_topic_depth` (a private method of another class).
