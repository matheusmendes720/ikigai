## CONVENTIONS

Deviations from stack defaults, all evidenced in-file:

1. **Specs-First is mandatory** (`specs/README.md`): write/refresh the spec in `vibe-ops/specs/` → mirror requirements into `vibe-ops/planning/PRD-*.md` → mirror contracts into `vibe-ops/contracts/*.yaml` → implement code referencing the spec → add tests that validate the spec. Specs precede code, not the reverse.
2. **Version suffix = lifecycle marker**, not just a label: `-v1` = deprecated, `-v2` = current, then SemVer (`-v2.1`, `-v3`). Deprecated v1 files stay on disk and are flagged `⚪ DEPRECATED` in `specs/README.md`.
3. **Append-only inside documents**: `schema-frontmatter-contract-v2.md` and `schema-pydantic-models-v2.md` declare themselves *"extensao append-only do v1"*; PRD-01/02/03 carry *"Regra Append-Only: Novas descobertas devem ser anexadas. Nada pode ser reescrito."*; `schema-planner-extension.md` is a *living spec* updated in place + reflected in `CHANGELOG.md`.
4. **Frontmatter is a hard contract**: every `.md` in the Planning domain **DEVE** have frontmatter (no frontmatter = ignored by the pipeline); `entity_type`, `id`, `status` are **always** mandatory; `status: active` = processed, `archived` = ignored.
5. **ID naming table** (`schema-frontmatter-contract{,-v2}.md` §1.2): Dream `S<int>`, Objective `O<int>`, Meta `M<int>`, Project `proj_<snake_case>`, quarter `Q[1-4]_YYYY`, wave `W[N]_Mmm_YYYY`, `tags` = snake_case array. Note this is uppercase-prefix + mixed case, unlike the lowercase colon-separated UEID canonical form.
6. **Computed fields are never hand-written**: `tw_project_key`, `c_comp`, `ic`, `total_target_hours`, `wave_count`, `completion_pct`, `streak_current` are annotated *"(gerado pelo pipeline, NAO editar manualmente)"*.
7. **CLI conventions** (`CLUSTER_PLAN_CLI_SPEC.md` §2): every command accepts `--json`; ISO 8601 dates; 24h `HH:MM`; duration in integer minutes (or float seconds); colour legend 🟢 3–5h / 🟡 5–6h / 🔴 6h+; idempotency enforced by UNIQUE constraints (re-run **updates**, never duplicates); **zero LLM**; **offline** (no network).
8. **Docs are Brazilian Portuguese; identifiers/keywords are English.** Status is expressed with 🔴🟡🟢 emoji, not text.
9. **Doc footer convention** `*<file> — vN.N — YYYY-MM-DD — <desc>*` — **only 14/34 files follow it**. Two use the older `*PRD-0N — … | vibe-ops v1.0.0 | 2026-05-10*` form; 18 have no footer at all (all `prd-*` mirrors, all `schema-*` docs, PRD-01/02/03, the templates, SPEC-05, the CHECKPOINT).
10. **Pydantic v2 idioms only**: `field_validator`, `Field(ge=, le=, pattern=, default=)`, `class X(str, Enum)`.
11. **Docs are contracts, not imports** — `schema-pydantic-models.md` states the models are "especificações — o código Python real …" lives elsewhere; the chunk never imports them.
12. **File naming splits by role**: hyphen-lowercase for specs (`spec-*`, `prd-*`, `schema-*`), UPPER_SNAKE for planning artefacts (`CLUSTER_PLAN_*`, `PRD-0N-*`, `TEMPLATE-*`, `CHECKPOINT-*`).

## ANTI-PATTERNS

**`schema-frontmatter-contract.md` §3 "O Que NÃO Fazer"** — bad → correction: frontmatter without `entity_type` → add it; FK to a non-existent entity (`parent_dream: "S99"`) → validate against the registry; tags with spaces → snake_case; BR date format `15/07/2026` → ISO 8601 `2026-07-15`; manual `tw_project_key` → let the pipeline compute it; IKIGAI vectors out of range (`passion: 1.5`, max 1.0); duplicate `id` across entities → ids must be globally unique.

**`schema-frontmatter-contract-v2.md` §3 (extended)** — `wave` as a free string (`"Julho onda 3"`) → FK `W3_Jul_2026`; habit without `anchor_wave` (orphan) → always bind to the active wave; `wave_count != 3` → structural constant 3; `cycle_count != 4` → structural constant 4; `lambda` outside [0.01, 1.0]; `resistance` outside 1–10; negative `qhe_weight` (range 0.0–1.0); `StudyPlan` with an empty topic array → min 1 active topic.

**`schema-planner-extension.md` §9** — wave without a parent cycle → *"Toda Wave DEVE ter um Cycle pai"*; duplicate phase tags in one interval (`+phase.learn +phase.earn`) → *"Maximo UMA phase tag por intervalo"*; habit with empty `tw_tags`; `status: active` with a past `end_date`; FK to a non-existent wave (`W99_Dez_2099`) → validate FK in the pipeline; `custom_days` outside 0–6 → validate range in Pydantic; `scheduled_time` set without `trigger_context=scheduled`; computing `streak_current` in frontmatter → *"Streak e COMPUTADO pelo pipeline"*.

**PRD-01 §"Proibido"** — `wave: "semana 3 de fev"` (free string); cycle without a valid `parent_phase`; two entities of the same type `active` simultaneously; skipping ReviewEvents without marking `skipped`.
**PRD-01 §"Obrigatório"** — every cycle → valid FK to an existing phase; ReviewEvents scheduled at wave/cycle creation; `active → completed` transition requires a completed `WAVE_END` ReviewEvent.

**PRD-02 §"Proibido"** — logging a streak without a matching daily log (artificial inflation); hardcoded `habit_level` (must come from H(t)); `weight_in_qhe` summing > 1.0 across all habits; changing `resistance` without a written justification. **§"Obrigatório"** — daily log before 23:59 to count toward the streak; `habit_level` recomputed after each log; QHE computed once per day (at the end); `streak_previous` updated whenever `streak_current` changes.

**PRD-03 §"Proibido"** — creating `StudyMaterial` without a valid `topic_id`; `completed_hours > estimated_hours` without updating `estimated_hours`; sessions longer than 240 min without break documentation; skills with `current_level > target_level`. **§"Obrigatório"** — `completed_hours` updated after every session; `hours_invested` synced with the sum of topics; `StudySession` needs minimal `notes` for traceability.

**Pipeline-level prohibitions** (`spec-cluster-plan-pipelines.md`) — *"Apenas aritmética + queries SQLite. Zero LLM, zero embeddings, zero NLP."* / *"Sem LLM, sem embeddings, sem charts interativos"* (ASCII markdown tables only). Also forbidden: network dependency; re-running a pipeline creating duplicates; future-dated journal entries or retroactive entries older than 7 days; `cold-start` rituals over 5 min and `warm-down` over 15 min (warning + review flag).

**Not stated anywhere in this chunk**: no `DO NOT`/`NEVER`/`ALWAYS` uppercase literals and no explicit deprecation notice inside the v1 files themselves — deprecation is only declared in the `specs/README.md` table.
